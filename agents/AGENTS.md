# Maintaining the PeopleSoft prompt pack

This directory is a portable prompt toolkit, separate from extension runtime code.

- Target PeopleTools 8.62 first. Ask for application pillar, application release/PUM image, database platform, Tools patch level, and Classic/Fluid context when they affect an answer.
- Keep examples generic and synthetic. Never commit employer hostnames, role names, schema customizations, credentials, or real student/employee records.
- Verify version-specific PeopleCode, Integration Broker, Component Interface, and Fluid behavior against Oracle 8.62 documentation. State uncertainty and require App Designer/schema evidence where needed.
- Browser field IDs do not establish record keys, scroll levels, or PeopleCode row paths. Distinguish browser observations from authoritative metadata.
- Keep database exploration read-only and bounded. Review effective-date/effective-sequence logic, keys, SetID, row security, and binds in the target schema.
- Keep canonical prompts, complete host exports, README and wiki descriptions consistent. No model- or employer-specific defaults.
- Content v4 uses canonical AGENT.md/GUIDE.md definitions and catalog.json; complete Copilot, Cursor, SKILL.md and Claude agent exports are generated by `npm run generate:agents`. Edit canonical sources, not generated files.
- Maintain the shared working-method block in PROMPT-TEMPLATE.md and every canonical definition; check:agents rejects drift. Keep exports standalone. Domain-specific exceptions belong outside that block.
- Retrieve only documentation sections needed for a claim; reuse current verified evidence and stop at a supported answer. Source lists are not mandatory reading. No claimed token/cost reduction without a measured host run.
- Intake, handoffs and output lists are conditional on task need. Keep the default single-agent workflow; delegate independent work only when authorized and worth the added context/coordination.
- Keep template copies under local-templates generic and unfilled. Filled pillar specialists belong outside this public repo and are never package inputs.
- Add source provenance, explicit uncertainty, caller/row context, valid exceptions, output/validation criteria and a discriminating evaluation case for each prompt. Never force current-row logic onto intentional history or infer row access from role names alone.
- Run `npm run check:agents` for catalog/link/export parity. Packaging uses an explicit file list, not a recursive archive of this directory. Model rubrics are not executed behavioral tests; source/structural checks do not establish IDE or real-system compatibility.
- Package with `npm run package:agents`; nothing here belongs in the Chrome extension zip.
