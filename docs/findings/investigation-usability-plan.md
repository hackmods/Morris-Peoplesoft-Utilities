## Ordered work and acceptance

1. **Inventory evidence and access.** Separate synthetic regression fixtures,
   representative sanitized files, and live-system results. Record source
   provenance, expected outcomes and limitations. No inferred patch identity or
   invented native export grammar. Current repository fixtures are synthetic.
2. **Use one consistent layout.** Three named steps: choose sources, preview and
   investigate, review and export. Keep sanitization, local-only behavior and
   unsupported native-format boundaries visible. Move detailed limits/examples
   into keyboard-accessible disclosures. Preserve every input, existing ID,
   accessible label, preview/review gate and session-only lifecycle. Do not add
   a forced wizard or new persistent data.
3. **Exercise tasks and failures.** A useful report, source/context edits after
   review, invalid/unsupported input, stale reads, clear/reload, copy fallback,
   download, keyboard focus, 320/390px layouts, axe including contrast, no
   automatic external requests and no investigation persistence. Compare derived
   results against independent expected outcomes, not only parser self-output.
4. **Representative evidence validation.** Scheduler: preserve source lines and
   distinguish unknown native text from recognized labels. IB: distinguish native
   artifacts from the explicit envelope/manual preparation. Configuration: compare
   approved before/after pairs with independently recorded expected changes and
   withheld secrets. Do not silently translate a source into the supported grammar
   and call that native-file support.
5. **Real PeopleTools validation.** On an approved environment, record Tools patch,
   application release/PUM separately, browser/version, source build, settings,
   exact read-only actions and observed results privately. Exercise relevant
   Process Monitor/IB entry points into an empty workspace and local file/report
   workflows in both browsers. Never run/replay jobs/messages or change server
   configuration to manufacture a test. Record unperformed scenarios explicitly.
6. **Integrate and verify.** Fresh dual build, lint/types, unchanged coverage gates,
   full sequential Chromium and installed-Firefox suites, Firefox/browser/store/
   compliance audits. Review source and rendered screenshots, including expanded
   guidance and failures. Update the existing PR and preserve frozen prior ZIPs.

storage, permissions, server state or release artifacts.
